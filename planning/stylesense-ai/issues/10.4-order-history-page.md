# 10.4 — Order History Page

**What to build:** The `/orders` route from `designs/page-orders`, replacing the `<h1>Orders (Protected)</h1>` stub. An accordion of order cards: the newest opens by default with a status tracker, line items, and summary; the rest collapse to a strip of thumbnails, item count, total, and **View Details**. Plus the `advance_orders` management command that gives the tracker something to track, and the header link that gives the page an entry point.

**Blocked by:** 10.3 — Checkout Flow UI

**Status:** done

## Decisions

**Header gets a plain `Orders` link, not an account menu.** Orders is the only
account page that actually exists — Wishlist and Profile are still `<h1>` stubs.
A dropdown would be one real destination and two dead ones, which is the same
mistake as the Checkout button 10.3 just finished fixing. The menu belongs in
whichever epic makes those pages real. The link is authenticated-only, and
disappears on logout.

**Status advances via a management command.** There is no warehouse and no
carrier webhook, so nothing would ever move an order past "Processing" and the
history page would show a column of identical rows forever.

**Dropped from the design:** the Delivery Address block (no address is
collected — see the epic decisions), and the **Reorder Items** / **Need Help?**
buttons, which have nothing behind them. Rendering dead controls is exactly the
problem this epic inherited.

- [x] `components/orders/OrderStatusPill.tsx` — per-status tone; cancelled is the only one that drops the accent, because it's the only status that isn't forward progress
- [x] `components/orders/OrderTracker.tsx` — Ordered → Processing → Shipped → Delivered. "Ordered" isn't a stored status: it's implied by the order existing, so it's always complete. A cancelled order gets an explanatory line instead of a position on the line it never finished
- [x] `components/orders/OrderCard.tsx` — collapsed and expanded states, `aria-expanded`/`aria-controls`, thumbnails with the gradient fallback, line items showing both prices with per-line savings
- [x] Line items link to the product **only when `product_id` is non-null** — a deleted product still has to render its snapshotted name, which is the whole point of 10.1's snapshot
- [x] `pages/Orders.tsx` — header per the design, accordion with the newest order open, empty state, error state
- [x] `management/commands/advance_orders.py` — `--order-number`, `--to`, `--dry-run`; terminal states never move
- [x] `SiteHeader` — authenticated-only `Orders` link, in both the desktop and mobile nav rows
- [x] `App.tsx` — real `Orders` page replacing the stub

## Verified in the browser

Four orders seeded across all four statuses:

- **Processing** → tracker at step 2 of 4
- **Shipped** → 3 of 4 checked, progress line at `scaleX(0.667)`, `aria-label="Order progress: Shipped"`
- **Delivered** → all 4 checked
- **Cancelled** → no tracker, *"This order was cancelled and will not be delivered."*
- Accordion: newest open on load; clicking it closes it; opening another closes the first (`aria-expanded=true` count never exceeds 1)
- Expanded card money checked by hand: 3 lines, ₹28,466 subtotal / −₹2,282 discount / ₹26,184 total, with **the same trousers in M and L as two separate lines** and "Saved ₹2,282" only on the discounted jacket line
- `advance_orders --dry-run` reports without writing; `--to delivered` walks multiple steps; a delivered order is not picked up on a re-run
- Header shows **Orders** when signed in, and it disappears on logout
- Second user at `/orders` → empty state, none of the first user's four orders
- Mobile 375px: no horizontal overflow, tracker hidden (`md:block`) as the design does
