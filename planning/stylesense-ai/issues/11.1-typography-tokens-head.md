# 11.1 — Typography, Design Tokens, and Document Head

**What to build:** Load the two typefaces the app has been referencing without ever loading, register them and the palette as Tailwind v4 `@theme` tokens, migrate the 28 arbitrary-value call sites, and replace the Vite scaffold's document head.

**Blocked by:** —

**Status:** ready-for-agent

## Decisions

**Playfair Display has never rendered.** `index.css` is one line, `index.html` has no font link, and Tailwind never loads font files — not for `@theme` tokens, not for arbitrary values. `font-['Playfair_Display']` compiles to valid, warning-free CSS and falls through to a system serif. That is the bug: 28 call sites across 17 files, zero visual effect, no build warning.

**Self-host via Fontsource variable packages, not a Google Fonts link.** Same-origin, bundled by Vite, no cross-origin round trip. Both default to `font-display: swap`, so FOUT behaviour is a wash between the two approaches. Note the naming trap, verified against the published package CSS: the variable builds register as `"Playfair Display Variable"` and `"Inter Variable"` — **not** the bare family names.

**Inter overrides Tailwind's own `--font-sans`.** This is the highest-leverage line in the ticket. Inter has zero call sites — there is no `font-['Inter']` anywhere — so every unstyled paragraph in the app currently renders in the system UI stack. Registering Inter as a *new* `font-body` utility would change nothing on screen until someone touched hundreds of elements; overriding `--font-sans` makes all nine existing pages inherit it with no edits.

**`@theme` carries colours, fonts and the type scale only.** In Tailwind v4 a `@theme` token overrides the default when the name collides, so declaring `--radius-lg` or `--shadow-md` would silently restyle every `rounded-lg` and `shadow-md` across nine built pages — the out-of-scope refactor wearing a hat. The type scale is safe by naming: `--text-h1`, `--text-body-lg`, `--text-label-caps` collide with none of Tailwind's own. Spacing is excluded because Tailwind's default is already a 4px base matching `DESIGN.md`'s grid.

**The markdown palette in `DESIGN.md` is canonical.** That file contains two conflicting palettes: a ~60-token Material-3 set in the YAML frontmatter (`surface-container-highest`, primary `#000000`) and 12 semantic colours in the markdown body. The app already implements the markdown set exactly — 156 uses of `#1A1A1A`, 73 of `#777`, 30 of `#E5E5E5`, 24 of `#F9F7F4`. The frontmatter set is generator output wired to nothing. Adopting the markdown palette is recognising what the app already is, not migrating to it.

**`#C9A96E` enters as a token even though nothing uses it.** The gold is the only warm note in an otherwise monochrome palette. Whether any surface spends it is a per-surface call in 11.6, 11.7 and 11.11.
