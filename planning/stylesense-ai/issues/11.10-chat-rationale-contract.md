# 11.10 — Chat Rationale Contract

**What to build:** Let the stylist attach a reason to each product it recommends, and stop it recommending things nobody can buy.

**Blocked by:** 11.8 — Style Profile: Schema, API, and Prompt Injection

**Status:** ready-for-agent

## Decisions

**Reasons arrive as `[[why:<id>]]` lines appended after the prose.** The existing `[[product:12]]` marker is **untouched**; `MARKER_RE` and `extract_product_ids` keep working unchanged.

Rejected: extending the marker to `[[product:12|reason]]`. `MARKER_RE` only matches complete markers, so during streaming the reader sees `[[product:12|The relaxed shoul…` as literal text until `]]` arrives. Today that window is three characters; with a sentence inside it, it is a long visible flicker in the middle of the prose. Line-based markers stream cleanly, and the frontend hides **everything from the first `[[why:` onward** while streaming — one rule, no flicker.

Rejected: deriving the reason from the surrounding prose. 11.11 puts the prose in the bubble and the cards directly beneath it, so a card whose "why" is a sentence lifted from above makes the reader read the same words twice, inches apart.

**The decisive property: no schema change at all.** `ChatMessage.content` already persists markers intact — deliberately, so history can rebuild card ordering — so reasons **reparse from stored content** on history load. Extending the marker instead would need per-relationship data on a plain M2M, which means a through-model, against this epic's standing rule.

**Non-compliance degrades silently, per pick.** Three failure modes — no `[[why:]]` line, a malformed line, a reason too long. All dropped or clamped. The prompt caps reasons at one sentence, roughly 120 characters. This matches the posture the marker contract already documents in `_attach_cited_products`: *"Ids come from a prompt-level contract the model can break, so they are validated against the database here — unknown ids are dropped silently."* A card without a why-line is still a good card; this is an enhancement, not a dependency. Rejected: all-or-nothing suppression, where one dropped line deletes the rationale from all five cards — a failure amplifier whose inconsistency reads as a bug. Rejected: retrying the call, which doubles latency and cost on a streaming interface to recover an enhancement.

**Both providers need verifying.** Sub-ticket 7.1 verified marker compliance on Gemini and the Groq fallback. This richer contract needs the same pass, and Groq is the weaker of the two — the likeliest to drop reasons under load.

**Retrieval filters `stock > 0`.** `ContextBuilder` filters on `embedding__isnull=False` and nothing else, so the stylist currently spends picks on unbuyable products — and with `top_k = 5`, each is 20% of a recommendation. This does *not* contradict 11.8's refusal to filter by size or budget: those are caveats the stylist can speak to, `stock = 0` is unavailability with no advice to give and no notify-me feature to fall back on.

- [ ] `SYSTEM_PROMPT` instructs `[[why:<id>]] <one sentence>` lines after the prose, capped
- [ ] Parser for why-lines in `product_markers.py`, keyed by product id
- [ ] Reasons attached to the `products` payload and reparsed from `content` on REST history
- [ ] Malformed, missing and over-long reasons dropped or clamped, never raised
- [ ] `ContextBuilder` filters `stock__gt=0`
- [ ] Compliance verified on **both** Gemini and Groq
