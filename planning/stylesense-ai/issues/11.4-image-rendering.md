# 11.4 — Image Rendering: Serializer, Ratios, and Fallback

**What to build:** Make the catalog actually render the photographs 11.3 seeds — fix the serializer that never sends one, unify six disagreeing aspect ratios, and replace the gradient placeholder with something quiet that also survives a broken hotlink.

**Blocked by:** 11.3 — Product Imagery: Curation and Seeding

**Status:** ready-for-agent

## Decisions

**The shop grid cannot show an image, and it is a one-line fix.** `ProductSerializer` — which backs the list endpoint — sends no image field at all, not `images`, not `image_url`. Meanwhile `ProductCard.tsx:63` reads `product.images?.[0]?.image_url ?? null`, a key the payload never contains, so it resolves to `null` on every render. The queryset **already** does `.prefetch_related("images")`, so the data is fetched and then dropped on the floor. This is a serializer field, not a query change.

**Everything converges on 4:5.** Measured, the app disagrees with itself: `ImageGallery` and `ChatProductStrip` are 4:5; `ProductCard` and `WishlistCard` are 3:4; `CartLineItem` is 10:13 and `OrderCard` is 18:23 — two of them not even round ratios. All six use `object-cover` and silently centre-crop whatever arrives. Sourcing at 4:5 means the product page, where cropping hurts most, never crops at all.

**Per-surface imgix crop params were rejected.** They only work on Unsplash — Pexels resize-by-param is observed convention, not a documented contract, and Pexels is the gap-filler — so the approach would break on an unknown subset of the catalog.

**Gradients become a quiet neutral placeholder.** The six pastels with a giant brand initial were scaffolding for having no images at all, loud because they had to fill an entire grid. They do not disappear when data lands: hotlinks fail, because the whole strategy points at someone else's CDN permanently, and `OrderItem.image_url` is a frozen snapshot with `default=""`, so every order already placed has an empty one. As a rare error state the fallback should read as intentional.

**`onError` gets wired.** Today the fallback triggers only when `image_url` is null; a URL that 404s renders a broken-image icon. On a hotlink-everything architecture that is the most likely failure mode, and nothing handles it.

**The duplicate dies.** `getGradient` exists twice — in `lib/product.ts` and copy-pasted inside `ImageGallery.tsx`. The replacement lives in one file.

- [ ] `ProductSerializer` carries a primary image URL; verify `ProductCard` renders it
- [ ] `ProductCard`, `WishlistCard`, `CartLineItem`, `OrderCard` converged to `aspect-[4/5]`
- [ ] `ImageGallery` derives its additional views as imgix crops of the single stored photo
- [ ] Neutral placeholder replaces `getGradient`, in one file
- [ ] `onError` falls back to the placeholder on every surface that renders an image
