# 11.7 — Home Page

**What to build:** The six-band home page from `designs/page-home`, with every band bound to data that already exists and every link landing somewhere real.

**Blocked by:** 11.2 — Site Chrome; 11.4 — Image Rendering

**Status:** ready-for-agent

## Decisions

**The hero CTA bounces to login and returns, and the plumbing already exists.** `CHAT WITH AI STYLIST` points at `/chat`, behind `ProtectedRoute` — which already passes `state={{ from: location.pathname }}`, and `Login.tsx:15` already reads it back and calls `navigate(from, { replace: true })`. Nothing to build. Guest chat is out of scope (see the epic).

**All three AI cards are rewritten.** The design's copy claims style-history analysis (no such thing exists), *"upload an inspiration photo"* (**flatly false** — no image input in `ChatInput`, the API, or the provider calls), and cross-brand fabric-and-fit comparison (partly true; fabric and fit are description boilerplate). Meanwhile this epic specifies three genuinely differentiating capabilities the copy never mentions: a rationale on every pick (11.10, 11.11), preference-aware styling (11.8), and adding to the bag without leaving the conversation (11.10). The cards are rewritten around those. Three cards, not two — the count is the band's composition.

**Trending Now reuses 11.5's `recommended` binding**, top 4, with `VIEW ALL` landing on `/shop?sort=recommended` so it shows the same ordering *continuing* rather than a different list. On the label: this is a merchandising label, not a capability claim — see the epic's decision.

**The Edit becomes For Her / For Him / Unisex.** The design's labels do not survive audit. *Summer Essentials* has no season field behind it. *New Arrivals* is real. *Best Sellers* would resolve to `-rating` — **the query Trending Now just took** — putting two bands of identical products under different labels on one page. Gender is the first fork a fashion shopper takes, the split is real (Women 22, Men 14, Unisex 14), and it is the axis 11.8 turns into a stored preference, so the tiles and the stylist agree about what matters. Each tile is one `?gender=` link and one of 11.3's editorial photos. Rejected: an "On Sale" tile — `discount_price` exists but `ProductFilter` has no filter for it.

**The trust bar keeps four tiles and swaps two.** Audit found half the band already true: **Free Shipping** is literally implemented (`cart_service.calculate_totals` returns `"shipping": Decimal("0.00")`) and **AI Styling** is real. *Easy Returns* has no model, endpoint or UI anywhere. *Secure Checkout* is a security assurance about a mock gateway. Both are replaced by capabilities that are fully built and currently never advertised: **Order Tracking** (`OrderTracker`, `OrderStatusPill`, `advance_orders`) and **Save & Compare** (the wishlist epic).

**One page for everyone.** No auth-state variation. 11.8 establishes the profile will be empty for almost everyone, so personalisation would make the page most people see the untested fallback; 11.5 already rejected the same shape for the default sort; and the hero CTA handles the returning visitor without it.
