# 11.9 — Profile Page

**What to build:** Replace the `/profile` stub with a style-first page that makes `style_preferences` editable.

**Blocked by:** 11.1 — Typography and Tokens; 11.8 — Style Profile backend

**Status:** ready-for-agent

Prototype: branch **`prototype/beautiful-stylesense`** (commit `3680b78`), not on `main`. `git checkout prototype/beautiful-stylesense` then `pnpm --dir frontend dev` and open `/prototype/profile?v=a|b|c|d`. Nothing to delete when this ships — the branch stays unmerged.

## Decisions

**Style-first, with Personal Information behind a disclosure.** With Security & Access out of scope, the design's seven-item account nav reduces to **two real tabs** plus My Orders and Wishlist, which are top-level routes already reachable from `SiteHeader` — so half the nav's items only navigate away. A nav where half the entries exit the page is a table of contents pretending to be an app shell. And Personal Information is three fields: first name, last name, and a disabled email, because `User` has nothing else. The profile is in this epic because `style_preferences` turns the stylist from generic into personal, and the layout should say that. Editing a surname is not why anyone opens this page.

**Sign Out stays in `SiteHeader`**, forced by having no account nav.

**Budget is preset chips, not the design's slider.** 11.8 made budget advisory — it reaches the model as prompt context, and nothing consumes the number precisely — so a control expressing `₹2,500 – ₹7,000` and one expressing `₹3,000 – ₹6,000` produce **identical behaviour**. The slider's precision has no consumer. It would also have cost a custom dual-range control the project does not own: two stacked `<input type="range">` with pointer-events juggling, ~25 lines of fiddly CSS plus keyboard and touch testing, on a page where nothing else needs one. Chips also keep the whole Style Profile in one interaction language alongside vibes, size and Shopping for. **Settle in implementation:** bands as drawn are mutually exclusive, so "anything under ₹6,000" spans two — either overlap them sensibly or make one `Any`. Revisit the slider if budget ever becomes a real filter.

**One page-level save.** Per-band saving is unsafe here: the Personal Information button would live *inside* a disclosure that is collapsed by default, so a name edit could be stranded with nothing on screen saying it was unsaved. Page-level also matches the API exactly — 11.8's write path is a single `PATCH /api/auth/me/` carrying preferences and name together. One dirty flag, one mutation, one invalidation of `["me"]`. Rejected: autosave, which means a PATCH per vibe chip unless debounced and removes the moment the shopper knows their preferences took effect.

**The callout ships, rewritten, linking to `/chat`.** The design claims these preferences create *"bespoke lookbooks tailored exactly to your aesthetic and fit"* — no lookbook feature exists, the same overclaim class cut from the home page. The replacement states the real mechanism: the stylist searches only what the shopper shops for, and **tells them** when something is outside their size or budget rather than hiding it. True, specific, verifiable in one conversation, and it explains an 11.8 decision the shopper would otherwise never see. Since an empty profile is the normal case, this panel is the page's strongest argument for filling it in — and the link closes the loop 11.8's once-per-conversation invitation opens.
