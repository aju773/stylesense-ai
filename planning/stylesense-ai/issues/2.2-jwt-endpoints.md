# 2.2 — JWT Auth Endpoints (DRF + simplejwt)

**What to build:** Register, login, refresh, logout, and user-info API endpoints using DRF and simplejwt with HttpOnly cookie transport.

**Blocked by:** 2.1 — Custom User Model

**Status:** ready

## Deliverables
- [ ] Install `djangorestframework` + `djangorestframework-simplejwt`
- [ ] Configure simplejwt for HttpOnly cookie mode
  - Access token: 5 min lifetime
  - Refresh token: 7 days lifetime
  - Tokens set as HttpOnly, Secure, SameSite=Lax cookies
- [ ] Enable `rest_framework_simplejwt.token_blacklist` in INSTALLED_APPS
- [ ] Endpoints:
  - `POST /api/auth/register/` — create user, return token cookies (auto-login)
  - `POST /api/auth/login/` — validate credentials, set token cookies
  - `POST /api/auth/logout/` — blacklist refresh token, clear cookies
  - `POST /api/auth/token/refresh/` — refresh access token cookie
  - `GET /api/auth/me/` — return current user data (protected)
- [ ] Registration serializer: accepts `email` + `password` only
- [ ] CORS configuration for local dev (frontend on :5173, backend on :8000)
- [ ] Verify: test all endpoints with curl/httpie, confirm cookies are set

## Key Decisions
- HttpOnly cookies (XSS-immune, persists across refresh)
- Token blacklisting on logout (security-first)
- Auto-login on registration (return cookies in register response)
- `/api/auth/me/` for frontend to check auth status on page load
- Password confirm is frontend-only; backend receives single `password` field
