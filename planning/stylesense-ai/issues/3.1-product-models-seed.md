# 3.1 — Django Product Models + Seed Data

**What to build:** A `products` Django app with Category, Product, and ProductImage models, plus a management command that reads `docs/products.json` and populates the database with 50+ fashion products. Running `seed_products` twice is safe (idempotent).

**Blocked by:** 01 — Project Skeleton & Core Architecture

**Status:** ready-for-agent

- [ ] Create `apps/products/` Django app
- [ ] `Category` model: name, slug (unique), description, image_url (nullable)
- [ ] `Product` model: name, slug (unique, auto-generated), description, price (decimal), discount_price (nullable decimal), brand, sizes (JSONField), colors (JSONField), gender, stock, rating, is_active, category FK, created_at
- [ ] `ProductImage` model: product FK, image_url, is_primary, display_order (leave empty for now — images come in ticket 04)
- [ ] Run `makemigrations` + `migrate`
- [ ] Management command `seed_products` that reads `docs/products.json`, creates Categories from unique category values, creates Products with `get_or_create` for idempotency
- [ ] Verify: run `seed_products`, confirm 50+ products in Django admin / shell

## Key Decisions
- Separate Category model (normalized, FK on Product) — stronger interview answer
- ProductImage model created now but left empty — no images yet, cards use styled fallback
- JSON fields for sizes and colors — fashion products have variable attributes, PostgreSQL indexes JSON natively
- Management command over fixtures — reads existing JSON as-is, idempotent, better interview talking point
