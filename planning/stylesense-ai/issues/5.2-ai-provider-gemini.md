# 5.2 — AI Provider Interface + Gemini Provider

**What to build:** An abstract AI provider base class (ABC) with an async `generate_completion(messages)` method that accepts OpenAI-format message lists. A concrete Gemini provider that translates messages into the `google-genai` SDK format and returns the AI response as a string. Verifiable by calling the provider in Django shell with a test prompt and getting a response.

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] Create `apps/chat/` Django app, register in `INSTALLED_APPS`
- [ ] Create `apps/chat/services/providers/base.py` — `BaseAIProvider(ABC)` with `async generate_completion(self, messages: list[dict], temperature: float = 0.7) -> str`
- [ ] Create `apps/chat/services/providers/gemini_provider.py` — translates OpenAI message format to Gemini `contents` + extracts system prompt into `config.system_instruction`, uses `client.aio.models.generate_content()`
- [ ] Add `google-genai` to `pyproject.toml` (`uv add google-genai`)
- [ ] Add `GEMINI_API_KEY` to Django settings (read from `.env` via `django-environ`)
- [ ] Verify: in Django shell, instantiate `GeminiProvider`, call `generate_completion` with a test message, confirm AI response is returned

## Key Decisions
- ABC over Protocol — runtime enforcement + shared base config (api_key, timeout)
- OpenAI message format as common interface — industry standard, Groq uses it natively, Gemini provider translates internally
- Async from day one — avoids sync→async rewrite when WebSocket streaming arrives (ticket 06)
- Role mapping: OpenAI `"assistant"` → Gemini `"model"` handled inside provider
