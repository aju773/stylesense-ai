# 5.3 — Groq Fallback Provider + Orchestrator

**What to build:** A concrete Groq provider using the `groq` SDK (AsyncGroq client), and a fallback orchestrator that tries Gemini first and falls back to Groq on transient errors. Provider list is configurable via Django settings + `import_string` for testability. Verifiable by simulating Gemini failure (wrong API key or mock) and seeing Groq respond instead.

**Blocked by:** 5.2 — AI Provider Interface + Gemini Provider

**Status:** ready-for-agent

- [ ] Create `apps/chat/services/providers/groq_provider.py` — uses `AsyncGroq` client, accepts OpenAI message format natively (no translation needed)
- [ ] Add `groq` to `pyproject.toml` (`uv add groq`)
- [ ] Add `GROQ_API_KEY` to `.env` and Django settings
- [ ] Create `apps/chat/services/exceptions.py` — `AIProviderTransientError`, `AIProviderPermanentError` base exceptions
- [ ] Map provider SDK exceptions: Gemini `errors.APIError` (429, 5xx) → transient; (400, 403) → permanent. Groq `RateLimitError`, `APIConnectionError` → transient; `AuthenticationError`, `BadRequestError` → permanent
- [ ] Create `apps/chat/services/orchestrator.py` — `AIProviderOrchestrator` loops providers, catches transient errors + logs warning, re-raises permanent errors, raises `RuntimeError` if all fail
- [ ] Create `apps/chat/services/factory.py` — `get_ai_orchestrator()` reads `settings.AI_PROVIDERS` list, uses `import_string` to instantiate
- [ ] Add `AI_PROVIDERS` to settings (Gemini first, Groq second)
- [ ] Verify: call orchestrator with valid keys → Gemini responds. Set bad Gemini key → Groq fallback kicks in with logged warning

## Key Decisions
- Catch only transient errors for fallback — permanent errors (bad API key, invalid prompt) abort immediately
- Settings-based DI via `import_string` — swap providers with `@override_settings` in tests
- No circuit breaker — overkill for this traffic level, simple fallback + strict timeouts sufficient
- Groq model: `llama-3.3-70b-versatile` — quality matters for fallback, 1,000 RPD is plenty for rare fallback usage
