# 5.4 — Conversation + ChatMessage Models

**What to build:** A `chat` Django app with Conversation and ChatMessage models that store chat history per user. Conversations belong to an authenticated user. Messages track role (user/assistant/system), content, which AI provider was used, and timestamps. Visible and manageable in Django admin.

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] Create Conversation model: user FK (to custom User), title (auto-generated or nullable), is_active (boolean, default True), created_at, updated_at
- [ ] Create ChatMessage model: conversation FK, role (choices: user/assistant/system), content (TextField), ai_provider_used (nullable CharField — null for user messages), created_at
- [ ] Add ordering on ChatMessage: `created_at` ascending (chronological)
- [ ] Register both models in Django admin with useful list displays
- [ ] Run `makemigrations` + `migrate`
- [ ] Verify: create a Conversation and a few ChatMessages in Django admin, confirm relationships work

## Key Decisions
- No `product_references` JSON field yet — that's a frontend concern for ticket 06/07 when product cards render in chat
- `ai_provider_used` tracks which provider answered — useful for debugging fallback behavior
- `is_active` on Conversation — allows soft-closing conversations without deletion
- Title is nullable — auto-generated from first user message in the chat service (ticket 5.6)
