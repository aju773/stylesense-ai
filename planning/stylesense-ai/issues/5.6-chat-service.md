# 5.6 — System Prompt + Chat Service

**What to build:** The central `ChatService` that wires everything together — loads conversation history (last 20 messages), builds product context via vector search, constructs the system prompt (StyleSense AI persona with hybrid catalog + general advice behavior), calls the AI orchestrator, and saves the response. This is the brain of the chatbot.

**Blocked by:** 5.3 — Groq Fallback + Orchestrator, 5.4 — Chat Models, 5.5 — Context Builder

**Status:** ready-for-agent

- [ ] Create `apps/chat/services/chat_service.py`
- [ ] Define the StyleSense AI system prompt — persona as a warm, professional fashion stylist. Hybrid behavior: recommend catalog products when relevant, give general fashion advice when catalog doesn't match. Instruct AI to mention product names and prices when recommending.
- [ ] Method `async send_message(user, conversation_id, message_text) -> ChatMessage`:
  - Load or create Conversation for the user
  - Save user's ChatMessage (role=user)
  - Load last 20 messages from conversation
  - Call context builder → get relevant products
  - Build messages list: system prompt (with product context) + history + current message
  - Call orchestrator.generate_completion(messages)
  - Save AI ChatMessage (role=assistant, ai_provider_used from response)
  - Auto-generate conversation title from first user message (if title is null)
  - Return the saved AI ChatMessage
- [ ] Use async ORM methods (`acreate`, `aget`, async iteration) throughout
- [ ] Verify: call `ChatService.send_message()` in Django shell → AI responds with fashion advice using catalog products

## Key Decisions
- System prompt includes product context dynamically per message — RAG pattern, not static context
- Last 20 messages — enough context for shopping conversations, predictable token budget
- Auto-title from first message — better UX for conversation list without requiring user input
- Chat service is a plain Python class — callable from views, WebSocket consumers, management commands
