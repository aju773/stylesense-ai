# 5.7 — REST Chat Endpoints + Throttling

**What to build:** DRF endpoints for creating conversations, sending messages (which triggers AI response), listing past conversations, and fetching conversation message history. All endpoints require authentication. Per-user rate limiting via DRF throttling prevents free-tier API abuse. End-to-end testable: a logged-in user can create a conversation, send a message, and receive an AI-generated fashion recommendation via curl or Postman.

**Blocked by:** 5.6 — System Prompt + Chat Service

**Status:** ready-for-agent

- [ ] Create `apps/chat/serializers.py` — ConversationSerializer (id, title, is_active, created_at, updated_at), ChatMessageSerializer (id, role, content, ai_provider_used, created_at), SendMessageSerializer (input: message text)
- [ ] Create `apps/chat/views.py`:
  - `POST /api/conversations/` — create new conversation for authenticated user
  - `GET /api/conversations/` — list user's conversations (newest first)
  - `POST /api/conversations/{id}/messages/` — send message, triggers ChatService, returns AI response
  - `GET /api/conversations/{id}/messages/` — list messages in conversation (chronological)
- [ ] Ensure all views are `async def` (async DRF views or native Django async views)
- [ ] Ownership check: users can only access their own conversations (return 404 for others)
- [ ] Create `apps/chat/urls.py`, wire into root `core/urls.py` under `/api/chat/`
- [ ] Configure DRF throttling in settings: `chat` scope at 5/min and 100/day per user
- [ ] Apply throttle classes to the send-message endpoint specifically
- [ ] Verify: using curl with auth cookies — create conversation, send "show me red dresses", receive AI response with product recommendations

## Key Decisions
- Nested URL structure: `/api/chat/conversations/` and `/api/chat/conversations/{id}/messages/`
- Send-message endpoint returns the AI's ChatMessage directly — frontend gets the response in the same request
- Throttling only on send-message (the AI-calling endpoint) — listing conversations/messages has no API cost
- Async views — consistent with async-first architecture, no sync_to_async wrappers needed
