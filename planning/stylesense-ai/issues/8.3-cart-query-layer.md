# 8.3 — Cart Data Layer (TanStack Query, not Redux)

**What to build:** The frontend's cart state. The ticket specified Redux; this slice deliberately uses TanStack Query instead — see the decision note below. Mutations apply their change to the cache immediately in `onMutate`, snapshot the previous cart, and restore that snapshot in `onError`. Because every mutating endpoint answers with the whole recomputed bag, `onSuccess` replaces the cache with the server's numbers outright, so no refetch is needed and the optimistic estimate never lingers.

**Blocked by:** 8.2 — Cart REST API

**Status:** done

## Decision: TanStack Query over Redux

The cart is server-owned state — the server computes every rupee. Query already
provides the exact optimistic-update primitive this needs (`onMutate` + rollback
context), and the project uses it for all other server state. One shared
`["cart"]` key means the header badge, the drawer, and the cart page read the
same cache with no synchronisation code at all, which is the thing "global
client state" was supposed to buy. Redux would have added a second server-state
cache alongside it, with its own invalidation rules and a real chance of drift.
Drawer open/closed is genuinely client state and lives in a small context.

- [x] `api/cart.ts` — `Cart`/`CartItem`/`CartTotals` types + `fetchCart`, `addCartItem`, `updateCartItem`, `removeCartItem`, `clearCart`
- [x] `hooks/useCart.ts` — `useCart`, `useCartCount`, `useAddToCart`, `useUpdateCartItem`, `useRemoveCartItem`, `useClearCart`
- [x] `optimisticallyUpdate` / `rollback` helpers — `cancelQueries` first so an in-flight refetch can't overwrite the optimistic state
- [x] `estimateTotals` mirrors the server formula for the pre-response frame only; every success overwrites it with the server's own totals
- [x] Optimistic add mirrors the server's upsert: a matching `(product, size, color)` bumps the existing line, otherwise a placeholder with a negative id is prepended
- [x] `useCart` is `enabled: isAuthenticated` — verified no `/api/cart/` request fires while logged out
- [x] `context/CartUIContext.tsx` — drawer open/close only; holds no cart data
- [x] `AuthContext` purges the `["cart"]` cache on login, register, and logout — without it the next user sees the previous user's bag from cache until the refetch lands
